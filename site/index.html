Terni runs the simulation tick of a grand-strategy game on the GPU. Model populations, markets, and empires, and keep every peer in lockstep.

Run the example Read the guide

C++20 · Vulkan 1.3 · Windows & Linux

Your game sets the rules.

Describe a world in text files and GLSL. Your engine sends commands and reads the results it needs. Terni runs the ordered compute stages and keeps the simulation state on the device.

  1. planet_growth

    Grow the population

    Apply growth and local modifiers per planet.

  2. empire_income

    Collect taxes

    Sum planet taxes into each empire’s income.

  3. empire_treasury

    Update the treasury

    Add the tick’s income to each empire’s balance.

Keep peers in sync

Fixed-point arithmetic and stateless randomness give compatible devices the same bits when they run the same world and commands. Compare state hashes to detect divergence.

Determinism guide

Give mods control of the rules

Mod folders can change starting conditions, balance, and the GLSL rules themselves. Run terni_check before publishing a mod.

Run Mini Galaxy.

Build Terni and run 100 ticks of a small world with planets, empires, and taxes. You’ll need CMake, Ninja, a C++20 compiler, the Vulkan SDK dependencies, and shaderc.

Setup instructions

Embedding Terni? Read the integration guide or explore the Godot and Flax plugins.

git clone https://github.com/ZBager/Terni.git
cd Terni
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/terni_run examples/mini_galaxy --ticks 100 --dump
